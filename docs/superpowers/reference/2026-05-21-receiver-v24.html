1:1 coverage: every field from internal/ui/bridge_fields.go + example.toml is here. Bridge: MiSTer host/port/source_port, host_ip, ui.http_port, data_dir, ffmpeg/ffprobe/ytdlp paths, video (modeline, interlace_field_order, aspect_mode, lz4_enabled, delta_lz4_enabled), audio (sample_rate, channels), MiSTer SSH (user, password) + Launch GroovyMiSTer action, logging.debug, all 11 hls_buffer fields. Adapters: Plex (4 fields + account), DLNA (4 + SSRF warning), URL (5 + cookies + yt-dlp hosts list), Torrent (10 fields), Jellyfin (3 + account), Streams (manifest refresh + provider list).
Scope chips on every field — HOT applies live (no restart), RECAST takes effect on next cast, REBOOT needs container restart. Matches the bridge's three-tier ApplyScope model — a save can compute the max-wins scope across all changed fields and tell you whether your changes apply live or need a restart.
Tag-list pattern for the URL adapter's ytdlp_hosts: each host is a pill chip with a remove (✕) glyph, with a dashed "+ add host" affordance at the end. Same pattern reusable for other list-of-strings fields (custom MIME types, blocked patterns, etc.).
Action result slot below the Launch button — DSEG14 status line (▸ Core loaded · session up · 4.2ms ACK) styled to read as a VFD readout from the same equipment. Same pattern works for any KindAction button: Probe MiSTer, Re-link Plex, Reset to defaults, etc.
What's still ahead: wiring the save handler to internal/uiserver/bridge_saver.go + per-adapter savers, mounting the tag-list pattern for ytdlp_hosts in the existing form-parse layer, and surfacing the action results inline (HX-OOB swap target already exists in the current UI).
